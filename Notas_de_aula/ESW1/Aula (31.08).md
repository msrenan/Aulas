# Introdução a Requisitos de Software

**Requisitos** são todas as necessidades e funcionalidades que o usuário precisa que o software a ser desenvolvido contenha, são o que descreve por quais meios e como o software deve funcionar.

**Técnicas de Elicitação de Requisitos** são estratégias para facilitar a comunicação entre engenheiro de software e cliente, de forma a maximizar a extração correta e eficiente dos requisitos desejados do cliente.

A documentação de requisitos é importante, pois muitas vezes o cliente tem a **ideia** de como deve funcionar, sem conhecer quaisquer meios necessários para desenvolver aquela funcionalidade. Por isso, a conversa com o cliente, na hora de desenvolver requisitos, deve ser feita de maneira conseguir extrair o máximo de requisitos possíveis de implementar, bem como, adicionar funcionalidades que o cliente pode não ter imaginado, mas que o engenheiro de software sabe que são imprescindíveis.

Os requisitos são divididos em:
- **Requisitos Funcionais (RF)**: São requisitos ligados a funções que o sistema deve fornecer, como o sistema deve reagir a entradas específicas, como o sistema deve se comportar em determinadas situações e podem também declarar o que o sistema **não** pode fazer.
- **Requisitos Não-Funcionais (RNF)**:  São requisitos ligados a restrições e padrões de qualidade que o software deve conter.


## Modelo User Story
- Documentação de requisitos **funcionais**.
- Modelo:
	- "**COMO** {perfil de usuário}, **EU QUERO** {realizar ação (requisito)} - **PARA** {justificativa/motivação do requisito}"
	- Um perfil de usuário pode ter várias Estórias, seguindo o modelo acima.
