
# Engenharia de Software: Histórico e Modelos de Processo

- **Processo de Software**: Define **o que**, **quem**, **quando** e **como** o desenvolvimento de um software deve ocorrer.
	- **Requisitos** -> O que deve ser implementado. Geralmente, vem do cliente final - o contratante.
		- *Todo conhecimento que se manifesta de forma permanente é conhecido como **Artefato***. Ex: Documento de Requisitos, Código, Diagramas.
- **Modelo de Processo**: Padrões de processos atualmente utilizados no mercado.

## Histórico

- **1950 - 1965**: Hardware estava em plena evolução, software era deixado de lado.
- **1965 - 1975**: Começam a surgir a multiprogramação (threads) e sistemas multiusuários, sistemas de tempo real e a primeira geração de *SGBD*s.
	- Nesse período, cresceram bastante o número de sistemas de software. Como não havia método - **processo de software** - as manutenções nesses softwares era dificultada, de certa forma, impossível.
- **1968 - *NATO Software Engineering Conference***: Conferência para discutir sobre a Crise de Software que estava ocorrendo na época. Ela foi causada, principalmente pela falta de processo de software, queda no preço do hardware e aumento do preço do software (já que não haviam muitos programadores ativos na época).
	- Alguns sinais da crise eram: Projetos atrasados, Projetos acima do orçamento, Software ineficiente e de baixa qualidade, Software que não atendia os requisitos do cliente, Problemas de gerenciamento e manutenção e Softwares que não eram entregues.
- **1975 - hoje**: Surgiram diversas novas tecnologias bem como uma grande evolução de hardware: Sistemas Distribuídos, Redes locais e globais (internet), Uso generalizado de microprocessadores, Hardware de baixo custo, Alto consumo de Software em escala global e cotidiana, Dispositivos móveis, IoT, Robótica e Popularização da IA.

# Engenharia de Software: Terminologia

Software pode ser definido como Programas de computadores construídos a partir de código por um programador, que manipula dados de qualquer natureza para atender às funcionalidades especificadas por um usuário. Já, a Engenharia de Software é a área da computação que foca em investigar desafios e propor soluções para resolver problemas de software **de maneira produtiva e com qualidade.**

Software é desenvolvido ou passa por um processo de engenharia, não é **fabricado** como no sentido clássico. ***Software não se desgasta, mas se deteriora.***

### Propriedades Inerentes e Essenciais do Software
- Complexidade
	- Quanto maior o Software, mais complexo ele é. Partes não se repetem. 
	- A computação é uma dos avanços mais complexos da história da humanidade.
	- Complexidade de Software não é **linear**.
- Conformidade
	- Complexidade pode ser arbitrária
	- Software deve se adequar ao contexto em que será utilizado:
		- Interfaces, instituições, governos, leis, clientes, etc.
- Modificabilidade
	- Capaz de ser alterado (outros produtos, como carros e prédios não podem sofrer tantas alterações.)
	- Software é maleável de maneira indefinida
	- Isso ocorre pois o software **precisa** se adequar ao contexto.
- Invisibilidade
	- Não é visualizável.
	- Não possuí representação geométrica.
	- Não há, ainda, um padrão de representação (UML)

### Áreas do SWEBOK
1. **Requisitos**: o que o sistema deve fazer para atender às necessidades do seu cliente.
	1. Funcionais: **o que** o sistema deve fazer.
		1. Funcionalidades de fato.
	2. Não Funcionais: **como** o sistema deve operar.
		1. Restrições e observações sobre a qualidade de serviço.
2. **Projeto de Software**: Definição dos principais **componentes** do sistema e suas **interfaces**.
3. **Construção do Software**: Implementação do sistema.
4. **Teste de Software**: Verificar se um programa apresenta um resultado esperado ao ser executado com casos de teste.
	1. Podem ser Manuais ou Automatizados.
		1. Verificação: É feita em cima dos requisitos e especificações. *Estamos fazendo corretamente?*
		2. Validação: É feita em cima do que o cliente deseja. *Estamos implementando o sistema certo?*
5. **Manutenção de Software**:
	1. Corretiva
	2. Preventiva
	3. Adaptativa
	4. Refactoring
	5. Evolutiva.
6. **Gerência de Configuração**: Todo software é desenvolvido usando um sistema de versionamento (exemplo: git), funcionando como um histórico de modificação do código, a base de snapshots - permitindo a recuperação de versões antigas.
7. **Gerência de Projetos**
	1. Negociação de Contratos (prazos, valores, cronograma)
	2. Gerência de RH (treinamento, contratação)
	3. Gerenciamento de Riscos
	4. Acompanhamento da concorrência, marketing, etc.
8. **Processo de Desenvolvimento de Software**
9. **Modelagem de Software**: Utiliza de representações de mais alto nível que o código para conseguir organizar ideias, explicar o "design" para os devs, documentar projeto e facilitar a compreensão do software em um todo.
10. **Qualidade de Software**:
	1. Externa: Correção, robustez, reusabilidade, etc.
	2. Interna: Organização, legibilidade, facilidade de manutenção, etc.
